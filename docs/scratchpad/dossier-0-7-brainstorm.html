Six small and six large, and one decision before any of them: reshape the current code or rebuild the core from its pieces. What Dossier is, zoomed out

Strip away the 43 blocks, the packs, the workspaces, and the release evidence, and Dossier does three things. An agent turns a prompt into a structured document. A person reads that document and decides inside it. The agent reads the decisions back and acts. Everything else in the codebase exists to serve one of those three, and anything that serves none of them is weight.

The strongest use today is the one you described: ask an agent for a plan with minor and major features, get a page you can skim and pick from, reply with numbers. That loop is Dossier's front door. 0.7 should make that loop excellent first, then let the same skeleton carry plans, reviews, releases, and incidents without changing how the page feels.

Four principles for the release:

  1. The static file is for reading and deciding. Authoring, editing, and studio tools live in dossier serve.
  2. One page shape, many kinds. A brainstorm and an incident review share the same shell, table of contents, facets, and summary table.
  3. Every control on the page must be explainable in one sentence to someone who opened the file cold.
  4. Budgets are features. The runtime, the stylesheet, and the block catalog each get a number, and the number goes down.

Where it fractured

The 0.5 and 0.6 arcs shipped every idea from the June brainstorm. Each one made sense alone. Together they produced a reader shell that carries authoring tools, six overlapping export concepts, and a runtime that every artifact pays for whether it uses it or not. Measured on the showcase example:

7 controlsIn the top bar: search, Edit, Blocks, Evidence, Theme Studio, theme toggle, Export. Four of them change the document rather than read it.
11 itemsIn the Export menu, plus 14 more buttons inside the Export Center. Source, state, merged, handoff, prompt, digest, and Markdown are seven names for two ideas.
5 modalsExport Center, block editor, evidence form, source viewer, shortcuts, and the palette ship in every file, including read-only briefs.
74 KBRuntime JavaScript inlined into every artifact. Most of it handles state packets, imports, and the block editor.
67 KBInlined CSS: base tokens, the skin layer, theme packs, and per-block styles for all 43 blocks regardless of which appear.
43 blocksFifteen of them are process variants that overlap: four kinds of board, four kinds of evidence, two kinds of diff, two kinds of gate.
385 KBThe showcase file. The typical example lands near 145 KB, of which the document model is under 20 KB.
28 toolsOn the MCP server, reading and writing ten packet schemas. The June brainstorm asked for four: create, render, read decisions, apply decisions.
2 renderersA 1,600-line string renderer and a 1,350-line React port that must stay in step for every block.

Rebuild or reshape

Taken together, the twelve moves below are a rebuild. The honest question is whether to do that rebuild inside the current tree, one subtraction at a time, or to stand up a new core beside it from the pieces worth keeping and cut over when the examples build. Both paths end at the same product. They differ in how long the code is in a half state and in what we let ourselves keep by accident.

A clean core would rest on five concepts, and nothing on the page would exist outside them:

  1. Kind. A preset naming the sections a document has, the facets its items carry, and how the reader replies.
  2. Section. Prose, a table, code, a diagram, a figure, a chart, a callout, or a board. Content blocks, no state.
  3. Item. A numbered thing inside a board with a title, a one-line summary, size, effort, impact, dependencies, and facets.
  4. Facet. A labeled paragraph on an item, in the fixed order the kind defines.
  5. Decision. What the reader said about an item: picked or not, a verdict, a note. The only state the file ever holds.

Everything the current product does maps onto these. A release checklist is a board whose items are gates and whose decision is done or not. An incident review is a board of findings with a timeline section in front. A patch review is a board of files whose facet is a diff. The concepts do not grow with the use cases; the kinds do, and a kind is forty lines.

modelOne JSON schema for kind, meta, sections, items, facets, and decisions. Stable ids everywhere. Old block type names accepted as aliases so every existing file still builds.
kindsSix presets shipped, custom kinds loadable from a pack. Each one is a small readable file, not code.
rendererOne string renderer, zero runtime dependencies. The React package becomes a typed wrapper that embeds the rendered document, so there is one renderer to keep correct.
readerThe runtime that ships in the file: table of contents, search, palette, theme, collapse, copy, decisions, pick. Under 20 KB, assembled from the modules the page needs.
studioEverything that edits: in-place text, block order, evidence, accent preview, patch import, CodeMirror. Injected by serve, never in the file.
agentThe skill plus four MCP tools: create from a kind, render, read decisions, apply decisions. Workspaces, release evidence, and packs keep their commands and consume the same two output files.
build-timeKept as is: Shiki, Graphviz, KaTeX, the unified diff parser, DOCX and PDF export, the CLI, the test suite, and the examples as parity fixtures.

The rebuild path in practice: create the new core beside the old one, port content blocks first against the examples, then boards and decisions, then the reader runtime, then serve. Cut over when every example builds and renders through the new core, delete the old tree, and ship that as 0.7. The old tree stays readable in git as reference the whole time. Expect three to four weeks against roughly the same for the twelve moves done in place, with less time spent half-broken.

The new shell

The front door layout becomes Dossier's shell. The table of contents moves to the left and goes sticky, the content column keeps a 68ch measure, features are separated by hairlines rather than boxed, and only four things on a page are objects: the facts tile, the layout list, the summary table, and the also-considered rows. The saturated block is the closing pick action.

1Shell reset

The static artifact's top bar drops to four things: where you are, search, theme, and one export.

How it works

The generated shell keeps crumbs, the search field, the theme toggle, and a single Export menu with three entries: Copy for agent, Download JSON, Print. Edit, Blocks, Evidence, Theme Studio, the dirty-state pill, the reading progress bar, the back-to-top button, and the Export Center all leave the static build. They are reachable only when the file is served from dossier serve, which injects them the way it already injects CodeMirror.

The command palette stays, but its command list is built from what is actually on the page, so a brief without decisions never offers "export decisions."

Reader

Opens the file and sees a document, not a workbench. Every visible control does something a reader would want. The keyboard shortcuts list shrinks to five entries that all work.

Agent

Nothing changes in authoring. The skill stops describing the Export Center and describes one action: copy for agent.

Unlocks

Item 8 becomes a refactor of code that is already out of the artifact, rather than a rewrite done under the reader's feet.

Risk

People who attach evidence or edit text inside a shared file lose that until they open it in serve. The README should say so in the first paragraph of Live Editing.

minor Effort S impact 4/5

2Left table of contents

The right rail becomes a sticky left column with grouped, numbered entries, and collapses to a chip row on narrow screens.

How it works

The existing table-of-contents builder already knows heading levels. It gains groups: kinds declare which sections are frame, which are pickable items, and which are the rest. Pickable items show their number in mono; frame entries show an en dash. Below 1100px the list turns into wrapping chip links and the group labels hide.

Reader

Sees the shape of the document before reading it: how many items, which are minor, which are major. Jumps by number. Scroll-spy still highlights the active entry.

Agent

Numbers come from item order in the board, so the agent never assigns them by hand.

Unlocks

The layout in the section above. Also frees the right side of the page, which is why the measure can widen to 68ch without the content column feeling cramped.

minor Effort S impact 4/5

3Type and token swap

The front door tokens become Dossier's tokens, with the accent moved to Dossier crimson and a light and a dark palette tuned separately.

How it works

The token file is rewritten to the thirteen names on this page: bg, paper, ink, muted, line, line-soft, accent, accent-ink, teal, violet, coral, plus the three font stacks. Three-state theming stays exactly as it is here. Body type is Figtree, one italic serif word in the title uses Instrument Serif, and identifiers use JetBrains Mono, each with a real fallback stack.

Web fonts are opt-in with meta.fonts: "google" so the default artifact keeps its no-external-assets promise. Without the flag the same scale and spacing render in the system stack, which carries most of the look.

Reader

The page reads as this one does. Light mode is the base, dark mode is retuned rather than inverted, and the toggle wins over the system setting in both directions.

Agent

Sets the accent with one field, meta.theme.accent, and nothing else. The fifty-token override surface goes away.

Unlocks

Item 11. Once the tokens are this small, skins and theme packs have nothing left to override.

Risk

Crimson as the accent sits close to a coral risk label, so the risk color moves to Dossier's ochre, which is what this page does. Confirm you like the crimson accent here before it becomes the default; blue as on the front door page is the alternative.

minor Effort S impact 4/5

4Facets block

A definition-list block with a fixed label order, plus size, effort, and impact fields that render as chips and meters.

How it works

A new facets block takes an ordered list of label and body pairs. Board items gain optional size, effort, and impact fields and an optional facets array. The renderer draws the meta row, the numbered title, the one-line summary, and the facet list exactly as the articles on this page. A facet labeled Risk or Note takes the colored label.

Reader

Every item on every page has the same facets in the same order, so items can be compared by scanning down one label column.

Agent

The skill gives the agent the facet vocabulary per kind and the rule that order never changes. Less prose freedom, more useful output.

Unlocks

Items 5 and 7. The summary table and the kinds are both derived from these fields.

minor Effort S impact 4/5

5Summary table from the board

The board emits its own summary table above the items: number, title, size, effort, impact, depends on.

How it works

A board with summary: true renders a table before its items, with the legend line generated from whichever fields are present. Titles link to the item anchors. Depends-on values are item numbers and are validated against the board, so a dangling reference fails the build.

Reader

Skims one table, decides what to read in full, and jumps. This is the single biggest reading improvement for long plans.

Agent

Never writes the table. It comes from the items, so it cannot drift from them.

Unlocks

Item 6, and a facts tile in the masthead that counts minor, major, and also-considered items automatically.

minor Effort S impact 3/5

6Pick by number

The closing action copies your selection as one line of text an agent can act on, with JSON behind it.

How it works

A pick block closes any board-carrying kind. It renders as the saturated block at the end of this page. Ticking items and leaving notes anywhere above fills it in. Its button copies text like Picked 1, 3, 4, 7. Notes: 3 keep blue accent. and the same content as a small JSON object. This replaces the decisions export, the handoff packet, and the prompt export for the reading case.

Reader

Reads, ticks, copies one line, pastes it into the thread. No menu, no packet name to learn.

Agent

Parses numbers and notes from the line or reads the JSON from the MCP tool. Both say the same thing.

Unlocks

Item 10. Once the reader's output is one line, the export contract can be one shape.

major Effort M impact 5/5

7Kinds as presets

A kind fixes the section order, the facet vocabulary, the summary table, and the closing action, so "make me a brainstorm" produces this page.

How it works

Six kinds ship in 0.7: brainstorm, plan, review, release, incident, and brief. Each is a small preset file: the frame sections it expects, the facet labels for its items, whether items are numbered, which fields feed the summary table, and what the pick block says. The generator validates a document against its kind and fills defaults, so a brainstorm with no pick block still gets one.

The existing process kinds map onto these: implementation and debug become plan with a different facet set; integration-loop becomes review.

Reader

Opens any Dossier and already knows where the summary is, where the items are, and how to reply. A release checklist and a feature brainstorm feel like the same product.

Agent

The prompt becomes the product. "Create a brainstorm dossier for X with six minor and four major features" is enough because the kind supplies everything else. The skill teaches six sentences, not forty-three blocks.

Unlocks

Item 12. It also makes the block catalog cut in item 9 safe, since kinds tell you which blocks matter.

Risk

Kinds can become a second, hidden block catalog. Keep each preset under 40 lines and readable by a person.

major Effort L impact 5/5

8Two-tier runtime

The static file carries a reader runtime under 20 KB; everything that edits the document moves to the served studio.

How it works

The runtime splits into a core and per-block modules. Core: table of contents and scroll-spy, search, palette, theme toggle, collapse, per-block copy, and the pick block. Block modules: checkboxes for action items, verdict and notes controls for boards, gate toggles for release checklists. The generator includes a module only when its block appears. Everything else, meaning in-place text editing, the block editor, evidence forms, state import, revision compare, Theme Studio, and CodeMirror, becomes the studio bundle that dossier serve injects.

Budgets are enforced by a test: core plus all block modules stays under 20 KB, base CSS under 30 KB, and the test fails when a change crosses the line.

Reader

Files open instantly and behave the same everywhere. A brief has no state machinery at all.

Agent

Unchanged for authoring. For editing round-trips it targets serve, where the full toolset lives.

Unlocks

A React port that only has to match the reader runtime. A plugin rule that plugins ship CSS and markup but no runtime, which keeps packs from re-bloating the file.

Risk

The largest change in the release and the one most likely to regress the existing examples. Do it after item 1 has already hidden the surfaces, so the split is mechanical.

major Effort L impact 5/5

9Block consolidation

Forty-three blocks become about twenty-two by folding the overlapping process families into one block each, with the old names kept as aliases.

How it works

Five families collapse. board absorbs review-board, process-board, finding-list, and cycle-board; the item schema carries verdict options and the facets from item 4. evidence absorbs evidence-log, verification-run, trust-report, and process-receipt, with an item kind of run, claim, observation, or receipt. diff absorbs patch-set and diff-view. gates absorbs release-checklist and verdict-gate. log absorbs decision-log, comment-thread, upstream-response, and integration-report.

Validation maps the old type names to the new ones with a deprecation warning and rewrites the model, so every existing example builds unchanged. 0.8 removes the aliases.

Reader

Fewer visual idioms to learn. A board looks like a board whether it holds features, findings, or work items.

Agent

Chooses from a catalog it can hold in context. The cheat sheet fits on one screen.

Unlocks

Roughly a third of the CSS and of the render code goes away. The React port gets smaller by the same amount.

Risk

The MCP tools and packet schemas name the old blocks. Do item 10 first so there is one contract to update instead of seven.

major Effort M impact 4/5

10One export contract

Seven export shapes become two files: the model with decisions merged in, and a decisions document both people and agents can read.

How it works

slug.dossier.json is the model with the reader's state already applied, which is what "merged JSON" is today. slug.decisions.md is the pick line, the notes, and the verdicts as Markdown with a small JSON front matter. Source, state packet, handoff, prompt, digest, and Markdown export go away as separate names. Copy for agent copies the decisions document. The MCP server exposes two read tools and one write tool over the same two shapes.

Reader

Never has to choose between five kinds of JSON. There is the document and there is what they decided.

Agent

Reads one Markdown document to learn what was decided and one JSON file to rebuild. The packet schemas shrink to two.

Unlocks

Items 8 and 9 become tractable, and the CLI's export subcommand loses most of its flags.

Risk

Workspaces and release evidence consume the state and handoff packets today. Give them the decisions document and a compatibility reader for old packets in 0.7.

major Effort M impact 4/5

11One theme

Skins, theme packs, and the in-artifact Theme Studio retire in favor of one default look with light and dark, and a single accent override.

How it works

The skin layer and the theme pack list are removed from the generator. The new default look is the one on this page. meta.theme.accent and meta.fonts are the only presentation fields. Theme Studio survives only inside serve, as a way to preview an accent and copy the one line into the JSON.

Reader

Every Dossier they open looks like the same product, which is what a document format should do.

Agent

Stops choosing between berry, forest, console-slate, and studio presets. There is nothing to get wrong.

Unlocks

Around 20 KB of CSS and the whole of the skins module disappear. The design record shrinks to one page.

Risk

Console Slate was built for dense process pages and this look is airier. Test the implementation-packet and incident examples in the new shell before retiring the skin.

major Effort M impact 4/5

12Skill and starters rewrite

The skill teaches kinds and facets instead of a block catalog, and every starter is regenerated in the new format.

How it works

SKILL.md is rewritten around one sentence per kind, the facet vocabulary, and the rule set for items: numbered, sized, with effort and impact, facets in fixed order. The blocks reference shrinks to the consolidated catalog. Starters for the six kinds are regenerated and each one builds to a page shaped like this one. The MCP server gains a tool that lists kinds and their facets, so agents that do not load the skill still author correctly.

Reader

Gets consistent documents from any agent, because the instructions the agent followed are short enough to be followed.

Agent

Loads a skill it can hold entirely in context. The first draft is right more often, which is the whole loop.

Unlocks

The README opens with one prompt and one screenshot instead of a feature map.

How to pick

First say rebuild or reshape. Then reply with the numbers you want, for example rebuild, all or reshape, 3, 1, 2, 4, 5, 6, 7, plus any changes. On the reshape path the order that keeps every example building is 3, 1, 2 for the look, then 4, 5, 6, 7 for the brainstorm kind, then 10, 8, 9, 11, 12 for the thinning. On the rebuild path the five concepts above are the spec and the twelve moves are its acceptance criteria.
